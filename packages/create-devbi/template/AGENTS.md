# 作業手順（AI 向け）

このフォルダは [DevBI](https://github.com/ishibashi0112/devbi) のダッシュボードのプロジェクトです。AI（Claude Code、Codex、Cursor など）がここでダッシュボードや指標を作る・直すときは、この手順に従ってください。

## プロジェクトの形

| 場所 | 中身 |
| --- | --- |
| `data/` | データのファイル（xlsx・csv など）。入力なので、頼まれないかぎり変えない |
| `models/<名前>.metrics.yaml` | 指標と軸。SQL はここ（`model` と指標の `sql`）にだけ書く |
| `dashboards/<名前>.dash.json` | タイルの並び。指標と軸を名前で指す（SQL は書かない）。画面の URL は `#/<名前>` |
| `dashboards/<名前>/*.tsx` | 自作タイル。組み込みのタイルで表せないときだけ |
| `api/<名前>.sql` | データベースから読むとき（`read_api('<名前>')`）。接続先は `.env.local` |
| `.devbi/`・`dist/`・`node_modules/` | 作られるもの。手で書かない |

ファイルの書き方の正本は `node_modules/devbi/docs/reference.md` です（入っている DevBI の版のもの）。ここにないキーや値を推測で使わず、そこで確かめてください。キーの一覧は `.devbi/dash.schema.json` と `.devbi/metrics.schema.json` にもあります（なければ `{{run}} gen` で作られます）。

## 手順

### 1. 調べる

- 使うデータのファイルごとに `{{run}} inspect -- data/<ファイル>` を実行し、列の名前・型・範囲・空の数・多い値・最初の行を見る。Excel を開かなくても中身が分かります。ほかのシートは `--sheet <シート名>`
- Excel の表の上に表題やメモの行があると、それを見出しとして読み、列の名前が `column2`… になり、どの列も文字（VARCHAR）になります。inspect が ⚠ で示す `--range`（例: `--range A2:K`）で読み直し、指標ファイルの `read_xlsx` にも同じ `range` を書きます
- 型の直し方や絞り込みは、ファイルを書く前に `{{run}} inspect -- --sql "SELECT … FROM read_xlsx('data/<ファイル>', sheet = '<シート>')"` で試せます（`models/` に試しのファイルを置かない）。指標ファイルの `model` が返す列は `{{run}} inspect -- <指標ファイルの名前>`
- `models/` と `dashboards/` の今のファイルを読む。新しく作るときも書き方の手本にする
- `{{run}} check` を実行して、今の状態を知る（もとからあるエラーと、自分が足したエラーを分けるため）

### 2. 方針を決めて伝える

ファイルを書く前に、次を短く伝えます。

- 指標ファイル: 読むデータ（`model`）、`time` にする日付の列、軸、指標（集計の式と表示名）
- ダッシュボード: 誰が何のために見るものか、どのタイルをどこに置くか、`date-range` の最初の期間

データだけでは決められないことは、推測で済ませず、聞くことと置いた想定を並べます。たとえば:

- 何を数えるか（行の数か、伝票の数か）、どの列が金額か
- 合計か平均か、平均の対象（完了したものだけか、すべてか）、空欄の扱い（未回答を除くか）
- どの日付で期間を区切るか（受付日か完了日か）、年度の始まりの月
- 除く値（返品・テストデータなど）
- 誰が、いつ、何を判断するために見るか

どのデータを使うかが分からないなど、答えがないと作れないときは、ファイルを書かずに質問で終えます。想定を置けば作れるときは、その想定で作り、最後の報告で確かめてほしいこととして並べます。

### 3. 書く

下の「書き方の決まり」に従って書きます。

### 4. 確かめる

1. `{{run}} check` を実行し、✗（エラー）がなくなるまで直す。⚠（注意）も読み、意図どおりかを確かめる（0 行の結果、確かめられなかったもの）
2. `{{run}} check -- --values` で、タイルが画面に出す数字を見る（`date-range` に最初の期間があれば、その期間で流します）。主な数字（kpi など）は、`{{run}} inspect -- --sql "…"` でデータから別に数えて、同じになるかを確かめる
3. `.tsx` を書いた・変えたときは `{{run}} typecheck` も
4. 終わったら、次を伝える
   - 作った・変えたファイル
   - `{{run}} check` の最後の行（「問題はありません」か、残した注意とその理由）
   - 確かめられなかったこと（見た目、最初の期間以外の数字など）
   - `{{run}} dev` で開いて見てほしいところ（`http://localhost:5173/#/<ダッシュボードの名前>`）と、そこに出るはずの数字（「2026年10月の問い合わせ件数は 150 件」など、人が知っている数字と比べられるもの）
   - 聞きたいことと、置いた想定

`check` が通っても、数字が業務として正しいかまでは分かりません。

## 書き方の決まり

### 指標ファイル（metrics.yaml）

- 1 行目は `# yaml-language-server: $schema=../.devbi/metrics.schema.json`
- データは `read_xlsx('data/x.xlsx', sheet = 'シート名')`、`read_csv('data/x.csv')` のように `read_` の関数で、プロジェクトからの相対パスで読む。`FROM 'data/x.csv'` はブラウザで読めない
- Excel の表の上に表題などの行があれば、`range = 'A2:K'` のように見出しの行から読む（終わりの行は書かない。最後の行まで読みます）
- 型は `model` で直す（`CAST(列 AS DATE)`、`strptime(列, '%Y/%m/%d')::DATE`、`TRY_CAST(列 AS DOUBLE)`）。`time` の列は日付か日時にする
- 指標と軸の名前は英小文字と `_`（`revenue`、`order_count`）。表示名は `label` に、書式は `format` に（`"¥#,##0"`、`"#,##0"`、`"0.0%"`）
- 指標は `revenue: { sql: SUM(金額), label: 売上, format: "¥#,##0" }` の 1 行で書けるが、式に `,`・`"`・`{ }`・`[ ]` があるとき（`COALESCE(SUM(金額), 0)` など）は、行を分けて書く。行を分けても、式に `: ` か ` #` があるとき、`'` か `"` で始まるときは、式全体を `'…'` で囲む（式の中の `'` は `''` に）

  ```yaml
  measures:
    done_rate:
      sql: COUNT(*) FILTER (WHERE 状態 = '完了') / COUNT(*)
      label: 完了率
      format: "0.0%"
  ```

- SQL（`model` と `sql`）の中の列の名前は、日本語や全角の括弧があってもそのまま書ける。空白（全角も）や半角の記号（`-`・`/` など）があるとき、数字で始まるとき（`1月`）は `"対応 時間"` のように `"` で囲む（`column:` と `time:` に書く列の名前は囲まない）
- 前年比・前年差・累計は SQL で書かず、`{ of: revenue, compare: previous_year, as: ratio }` や `{ of: revenue, running: fiscal_year }` にする（`time` が要る）
- 単価や率は、合計どうしの割り算にする（`avg_price: { sql: revenue / quantity }`）。行ごとの比を `AVG` しない。1 行に 1 つの点数（満足度など）の平均は `AVG(列)` でよい（`AVG` と `COUNT(列)` は空欄を数えない）
- 件数は、数えるものに合わせる（明細の行なら `COUNT(*)`、伝票なら `COUNT(DISTINCT 伝票番号)`）
- 少ないほうが良い指標（クレームの件数、不良の数、対応にかかった時間など）には `better: lower` を書く。kpi の比較の色が逆になる（増えると赤）。その指標の比較（`of`）にも引き継がれる

### ダッシュボード（dash.json）

- 最初のキーは `"$schema": "../.devbi/dash.schema.json"`。`"metrics"` に指標ファイルの名前
- グリッドは 12 列。`x + w` は 12 まで、タイルは重ねない
- 並べ方の目安（上から）: 期間 `date-range`（`w` 12・`h` 1）、数字 `kpi`（`w` 3・`h` 2 を 4 つずつ）、推移とランキング（`bar`・`line` は `w` 8・`h` 4、`barlist` は `w` 4・`h` 4）、表 `table`・`pivot`（`h` 5）、説明の `markdown`（`w` 12・`h` 2）
- 種類の選び方: 1 つの数字は `kpi`、時間の推移は `bar`（比べる系列があれば `line`）、内訳の推移は `area`、順位は `barlist`（`limit` 10 ほど）、2 つの項目の掛け合わせは `pivot`、一覧は `table`（`limit` を付ける）、値で絞る入口は `select`、見る人が明細を自由に並べて集計する場は `explore`（`w` 12・`h` 6。`model` の列をそのまま読み、`query` は `filters`・`limit`・`period` だけ。`options.layout` の列名も `model` の列名。Perspective を読むので重く、1 つのダッシュボードに 1 つまで）
- `date-range` の最初の期間（`options.default`）は、見る人の使い方に合わせる。毎日見るなら `latest_day`・`last_7_days`・`latest_week`、月の会議なら `latest_month`・`previous_month`、四半期なら `latest_quarter`、年度なら `latest_fiscal_year`（`time` に `fiscal_year_start` が要る）。「最新」「直近」は、今日ではなくデータの最終日が基準
- `date-range` の期間は、その `time` の列を持つ指標ファイルのタイルすべてにかかる。「いま対応中のすべて」「全期間の累計」のように期間に関係なく出すタイルは、`query` に `"period": false` を書く（期間だけが外れ、地域のクリックなどほかの選択はかかる）
- 比較の指標（`compare`）は、`time` のあるクエリか、`date-range` のあるダッシュボードで使う（全期間のままだと空になる）。`previous_period` は、月・週・四半期・年の期間なら前の月（週…）の同じ日と、`last_7_days` などなら同じ日数だけ前と比べる。kpi の 2 つ目からの指標は、`as` が `ratio`・`change`・`delta` だと、増えると緑・減ると赤になる（`better: lower` の指標は逆）
- `sort` は配列（`["-revenue"]`。`-` で大きい順）
- タイルの `id` は英小文字と `-`、`title` は日本語

### 自作タイル（.tsx）

- 組み込みのタイルで表せないときだけ書く
- `export const query = defineQuery({ ... })` でデータを宣言し、`TileProps<RowOf<typeof query>>` を受け取る。`fetch` や SQL で別にデータを読まない
- 値は `format(値, 列の名前)` で表示し、クリックでの絞り込みは `select(...)` で

### しないこと

- `data/` のファイルを変える・消す（頼まれたときを除く）
- `.devbi/`・`dist/` を手で書く
- 接続先やパスワードを、git に入るファイルに書く（`.env.local` に書く）
- 頼まれていない指標・軸・ダッシュボードを消す、名前を変える（ほかのダッシュボードや自作タイルが名前で使っている）
- `{{run}} check` を通さずに終える
